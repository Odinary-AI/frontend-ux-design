# 设计契约：DesignSystemManifest

本文件定义 D2 与提取模式的输出内容。它描述项目选定的设计系统与行为，不是第二份产品需求。依据和冲突处理遵循 [入口](../SKILL.md#共同约束)。

## 最小表达

先引用已有 token、组件库、设计稿与行为文档。全新系统需覆盖下表九个适用维度，不适用项写简短理由；局部工作仅列受影响维度、原有来源及新增缺口，不复制整套九节。

| 维度 | 要明确的决定 |
|---|---|
| 色彩 | 背景、表面、正文、强调与适用的语义状态；前景/背景合法搭配。若支持多个主题，逐主题核对搭配与切换。使用项目原生格式，跨格式转换只在消费者需要时做 |
| 排版 | 字体及回退、角色、字号层级、字重、行高、行宽；中文按 [中文参考](typography-cn.md)，正文与数据/控件区分 |
| 间距 | 项目间距标尺、组内/组间关系及容器首末内容边界；明确由容器padding、布局gap或内容margin负责哪段距离，允许有理由的组合。沿用已有基数，不为统一风格重写布局 |
| 布局 | 目标设备、容器、栅格、断点行为；折叠菜单、表格与长内容如何适应窄屏 |
| 表面与层级 | 圆角、边框、阴影、浮层关系；优先组件原生层级机制 |
| 动效 | 有无必要、用途、项目时长/缓动与降级；默认值只见 [动效参考](motion.md) |
| 交互与无障碍 | 控件名称、键盘/触摸路径、焦点与反馈；行为检查见 [交互参考](interaction.md) |
| 组件与状态 | 复用组件及变体、适用状态、空/加载/错误/成功等流程状态；不要求静态内容拥有无意义的 disabled 状态 |
| 文案 | 用户术语、动作命名、状态信息、错误恢复与真实内容来源 |

语义 token 表达用途。能够复用的值先复用，新增值说明用途与原因。不同角色恰好使用同一色值，不代表可以删除角色；相似色也不能仅因接近就自动合并。

局部迭代保留原契约中仍适用的决定，用实际渲染核对消费结果：主题是否保留文字角色、容器边界是否叠加间距、长内容是否改变分组。发现与预期不符时追到覆盖来源，不只检查token声明存在。视觉与运行证据的取得方式统一见[评审规则](review.md#证据与结论的对应)，不在契约中另建一套通过标准。

## 任务路径与方向来源

本次改变多步骤或跨页面结构时，引用按[任务路径](task-flows.md)选定的流程、产品依据与未决条件；只调整局部控件则沿用已有路径。方向经过比较时，保留选定方案、服务的用户任务、关键取舍及参照位置即可，不存另一套品牌规范或把未选方案变成实现待办。

数据表达涉及的判断目标、口径来源与联动约定按[数据界面](data-ui.md)引用现行定义，未知不补造；这些决定落在上表的布局、组件、交互和文案中，不增加所有任务必填的章节。随后只为会改变行为的节点补状态。

## 交互契约

仅列任务涉及且会改变行为的状态。可直接补充已有组件文档，或用紧凑表：

| 动作 | 状态变化 | 可见/可访问反馈 | 恢复与保留 |
|---|---|---|---|
| 示例：保存修改 | 编辑 → 请求中 → 成功/失败 | 请求中防重复提交；成功提示；失败定位原因 | 失败保留输入并允许重试；离开前按项目规则处理未保存内容 |

覆盖正常路径与最重要的失败路径，按实际需要加入无权限、空结果、取消、并发或过期状态。不为纯静态页补写虚构服务。

## 页面例外与复用

页面特有布局可以不同，但需说明继承的全局 token、组件与例外适用范围。页面例外不能自动覆盖无障碍与内容真实性要求。单纯希望另一种外观不意味着需要新建全局 token。

提取记录附来源位置（代码行、设计节点或截图范围）、观察到的状态，以及哪些值是近似推断。产品 intent 不能只凭颜色猜测；缺失信息标未知，不伪造 rationale。
