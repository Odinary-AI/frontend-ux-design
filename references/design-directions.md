# 方向案例：从设计问题到表达

仅在 D1 的方向或构图仍开放且需要参照时读取。先找要解决的设计问题，再选择机制；行业、风格名称和下方视觉示例都不能自动决定方案。已确认的品牌、布局和项目组件继续作为依据，不因查阅案例重开决定。

## 机制案例

| 当前问题 | 可以借鉴的机制 | 适用与取舍 |
|---|---|---|
| 用户需连续理解一段内容 | 用标题、段落、图文位置和节奏建立阅读顺序；正文与旁注分清 | 内容阅读、说明和产品故事；不把需要反复对照的信息分散成漫长叙事 |
| 用户需同时核对多项信息 | 对齐比较维度，按相关性分组；用字重、位置和留白区分主次 | 密集工具与对比页面；保留必要上下文，不能以“高级留白”拉远有关数据；数据表达另见[data-ui](data-ui.md) |
| 用户需要看懂作品或产品差异 | 让真实作品、演示或关键细节承担证据，界面围绕其组织 | 展示、营销；缺少真实素材时标注待替换，不用假统计或无关大图补气势 |
| 用户必须完成有依赖的选择 | 按依赖展示信息，保留进度与返回路径；不相关的选项延后 | 多步骤任务；可同时完成的简单输入可同屏，不把“渐进展开”变成多余向导；路径按[task-flows](task-flows.md) |
| 题材需要鲜明识别 | 将题材中的材料、结构、语言或节奏转成一处主要表达，其余部分保持一致 | 已授权的品牌探索；表达不能抢过主要内容或让工具操作等待；熟悉结构也可以有鲜明身份 |

每次借鉴能说明“当前任务需要什么 → 参照提供什么机制 → 怎样适配真实内容与项目约束 → 代价是什么”即可。只取可迁移机制，不能把多个参考的颜色、组件和装饰各取一块直接拼接。找不到适用案例时自行推导，不强行归类。

## 视觉表达示例

以下保留启动素材，供未确定的色彩/字体维度参考；不是已验证的完整主题，也不提供行业选型表。色值只是表达候选，须按实际角色组合检查对比度；字体沿项目资产、目标文字与回退选择。布局间距、断点、动效和组件不能从风格名称推断，统一进入[设计契约](design-contract.md)。

| 表达示例 | 可借鉴的视觉语法 | 配色与字体候选 |
|---|---|---|
| 编辑极简 | 细线与排版层级，减少容器装饰；深浅主题均可 | 深底 #0f0f14、文字 #ffffff、强调 #5e6ad2；Inter Tight / Inter，中文回退 PingFang SC |
| 电影深空 | 大尺度影像与少量强色形成焦点 | 黑 #000000、品红 #e219eb、青 #00e5ff；Sora。需真实影像或明确视觉主题，不能遮蔽文本 |
| 暖纸手作 | 材料感与正文节奏表达亲近 | 纸白 #faf8f2、墨色 #2d2a26、赤陶 #9d5f4d；Source Serif，中文宋体。暖色不自动代表所有生活品牌 |
| 数据终端 | 稳定对齐与清晰数据层级 | 底色 #181818、文字 #e0e0e0、强调 #faff69；数据可用 JetBrains Mono 或等宽数字。数据任务不要求暗色或荧光色 |
| 粗野撞色 | 强边界与直接的字形建立节奏 | 白 #ffffff、黑 #000000、橙 #ff6600；Unbounded / Space Grotesk。冲击不能损害文本读取 |
| 液态玻璃 | 用透叠关系解释层级 | 随内容调整透明表面，字体可参考 Outfit；复杂背景需核对可读性和渲染成本，无层级用途时可不用 |
| 杂志编辑 | 图文主次与不等宽分栏表达内容关系 | 暖白 oklch(98% 0.005 80)、墨色 oklch(30% 0.02 60)；Playfair Display / Source Sans Pro，中文宋体标题与黑体正文 |
| 日式禅意 | 留白与少量细节支持慢节奏观看 | #f7f5f0、#33322e、#7a8b78；Zen Old Mincho / 中文宋体。不把密集工作界面强行拉疏 |
| 工业实用 | 严格对齐、明确分区和直接标签 | 铝灰 #e8e6e1、近黑 #1a1a1a、橙 #d97900；IBM Plex Sans / Mono。编号仅用于真实顺序 |
| 复古未来 | 用历史媒介的色彩和字形形成题材联系 | 深棕 #1a1206、琥珀 #ffb000；VT323 / IBM Plex Mono，中文黑体回退。纹理不能影响读数 |

## 从参照回到方案

D1 的候选应能表达当前内容的组织差异或明确的视觉取舍；不靠同一布局更换风格名称制造多方案。在已有品牌中可以比较列表/分组、详情位置或信息强调，保持 token 和组件来源一致。

当文字不足以判断时，沿[D1](../SKILL.md#d1形成方向仅方向尚未确定时)用同内容、同状态、同目标视口的小范围可见方案比较；只探索开放维度。选定后留下理由与参照，归入契约；未选方向不成为后续实现清单。无需为了“独特”消除用户熟悉且有效的惯例。
