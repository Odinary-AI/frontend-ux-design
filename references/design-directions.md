# 方向案例：从设计问题到表达

仅在 D1 的方向或构图仍开放且需要推导或参照时读取。先找要解决的设计问题，再选择机制；行业、风格名称和下方视觉示例都不能自动决定方案。已确认的品牌、布局和项目组件继续作为依据，不因查阅案例重开决定。

## 从调性到构图

- **将调性落在可见关系上。** 找到 brief、题材、实际内容或使用场景里支持它的事实，再选择最能表达该事实的几个维度，例如字形和字重、信息密度、明暗与色彩对比、边缘质感、动作幅度。同一句“有力度”，活动海报可用大字与色块对比，排障界面可用紧凑、对齐的记录和清楚的异常位置。把确定的选择交给[设计契约](design-contract.md)，不固定填满所有维度。
- **用灰度解决结构问题。** 当文字描述不足以判断时，用真实内容长度和主视口，画出关键区域的内容块、阅读起点、任务入口与结果位置。临时去掉配色、装饰和质感，检查主次、分组、空间分配，以及完成当前任务所需的信息是否就近。核心动作会改变信息结构时，画出相关前后状态。并列比较或多任务工作区可有同等权重的区域；目标是关系清楚。最后放回承担信息的图片与色彩，核对真实内容，灰度草图不能证明色彩辨识、可读性或操作已通过。
- **有方向差异时才比较。** 复用相同 brief、内容、状态和目标视口，比较阅读顺序、对象关系、主次或任务路径。若两个方案只换颜色而当前问题是找不到入口，优先调整结构；若待决定的正是配色，保持结构相同是合理对照。图片决定构图时，先按[素材与构图](assets.md#素材与构图)确认主体、来源和关键裁切。

## 机制案例

| 当前问题 | 可以借鉴的机制 | 适用与取舍 |
|---|---|---|
| 用户需连续理解一段内容 | 用标题、段落、图文位置和节奏建立阅读顺序；正文与旁注分清 | 内容阅读、说明和产品故事；不把需要反复对照的信息分散成漫长叙事 |
| 用户需同时核对多项信息 | 对齐比较维度，按相关性分组；用字重、位置和留白区分主次 | 密集工具与对比页面；保留必要上下文，不能以“高级留白”拉远有关数据；数据表达另见[data-ui](data-ui.md) |
| 用户需要看懂作品或产品差异 | 让真实作品、演示或关键细节承担证据，界面围绕其组织 | 展示、营销；缺少真实素材时标注待替换，不用假统计或无关大图补气势 |
| 用户必须完成有依赖的选择 | 按依赖展示信息，保留进度与返回路径；不相关的选项延后 | 多步骤任务；可同时完成的简单输入可同屏，不把“渐进展开”变成多余向导；路径按[task-flows](task-flows.md) |
| 题材需要鲜明识别 | 将题材中的材料、结构、语言或节奏转成一处主要表达，其余部分保持一致 | 已授权的品牌探索；表达不能抢过主要内容或让工具操作等待；熟悉结构也可以有鲜明身份 |

每次借鉴能说明“当前任务需要什么 → 参照提供什么机制 → 怎样适配真实内容与项目约束 → 代价是什么”即可。只取可迁移机制，不能把多个参考的颜色、组件和装饰各取一块直接拼接。找不到适用案例时自行推导，不强行归类。

## 推导示例

以下为自编情境，展示如何作取舍，不是用户研究结论或默认模板。仅在遇到对应结构问题时参考；已确认的方向继续保留。

### 从实物题材推导视觉

假设社区修理站要让居民看清可修物品并找到登记入口，brief 要求“亲切、有行动力”，已有工作台实拍。亲切可以来自自然光下的器具、清楚的标题和日常用语；行动力来自紧邻维修范围的登记入口、明确的时间与地点。先用灰度比较满幅照片和图文并列，若照片在窄屏压住工具主体或文字，改为图文上下相接。高饱和色可以用于活动辨识，登记状态仍使用项目既有语义色。若任务改为站内师傅快速核对预约，则将同一照片退到需要识别实物的位置，密度由记录量和操作频率决定。

### 同时比较方案

假设用户需比较三个服务方案的价格、容量、协作权限和限制，字段口径已有来源，视觉方向仍开放。主要任务是跨方案核对差异，而非逐个欣赏介绍。

- **候选**：独立卡片适合各方案有较多独立介绍的情形，但字段位置不一致会增加对读成本；对齐列表适合字段少且可在一行读完的内容；比较表适合反复沿同一维度横向核对。轮播能突出单个方案，却把同时对读变成来回切换。
- **本例选择**：方案为列、比较维度为行的表格，方案名称和选择入口对应明确；复用项目文字角色、边框和间距。价格周期、单位与限制按真实口径呈现，不凭视觉需要添加“最受欢迎”。窄屏保留必要的二维比较和局部滚动，不让整页溢出；数据规则见[数据界面](data-ui.md)。
- **代价与改变条件**：表格可能需要横向滚动；若内容变为以作品图片和独立叙事为主，卡片可能更适合，应按任务重选，而非将表格定为通用答案。
- **如何核对**：用相同内容、状态和目标视口比较关键区域；检查能否找到某项限制、横向核对同一维度并选择对应方案，长名称和窄屏仍保留身份与数值关系。未实际操作时只报告结构推演，不声称比较效率已提升。

### 有依赖的配置

假设导入任务已有业务约定：先选数据来源，再按真实字段作映射，预览后确认导入；通知偏好可稍后设置。本例不授权改变其他产品的前提。

- **候选**：全同屏利于回看，但来源未确定时后续字段尚无依据；每个字段单独成步会割裂需要对照的信息；按依赖分阶段、阶段内同屏，可保留字段间的比较关系。
- **本例选择**：选择来源 → 同屏字段映射 → 预览并确认 → 查看导入结果。只把可选的高级映射设置渐进展开，必要字段与错误保持可见；通知偏好延后到相关场景。返回更换来源时，按项目规则标出失效映射并要求重新核对，不能保留旧映射冒充有效配置。
- **代价与改变条件**：分阶段增加往返；若来源已固定且映射简单，可以合并页面。若通知设置确为业务前提，则保留，不能套用本例延后。
- **如何核对**：沿[任务路径](task-flows.md)检查从来源到可识别结果的路径，并检查返回更换来源、校验失败及取消后的恢复。异步导入须区分“已提交”和“已完成”，状态与保留策略引用现有[设计契约](design-contract.md)，不自行承诺后端能力。

所选结构及关键取舍由现有契约承接；不要求为每次设计复制以上格式。

## 视觉表达示例

### 可渲染的设计组合

方向开放且需要具体参数时，读取[四类组合](../assets/design-recipes.html)中与当前问题有关的区块及 CSS；不默认读取或套用全部。该文件是样例参数与画面的唯一来源，下表只解释机制。所有内容为自编示例，不是项目事实或经过用户研究的推荐。

| 用途 / 样例 ID | 解决的问题与机制 | 取舍 / 不适用 |
|---|---|---|
| 阅读 / reading | 中文段落、旁注和稳定正文行宽；标题/正文/旁注由字形、位置与间距共同区分 | 适合连续理解；精确对读保留同屏关系，不拆成长篇叙事 |
| 工具 / tool | 主字段对齐、正文与表格分别定密度、数字使用等宽数字；表格区域保留必要滚动 | 不把编号当真实统计；复杂操作和筛选须沿项目组件与数据口径补齐 |
| 营销 / marketing | 价值说明与具体观察路径双栏相邻，一项明确的下一步；窄屏按阅读顺序重排 | 仅开放方向可采用；缺少实际证据不加假客户、效果数字或无关影像 |
| 展示 / showcase | 图形主导、说明退后；暗色表面配合法文字角色，窄屏顺序展开 | 示意图不等于真实作品；替换真实素材后重验比例、内容与对比度 |

消费顺序：确定要解决的问题 → 核对已定规范与仍开放维度 → 读取适用组合 → 保留/调整布局、排版或配色，并解释取舍 → 将选定决定引用到契约。无匹配就自行推导，说明未采用资料；不强迫分类。颜色角色成对使用：背景/正文、表面/表面文字、背景/辅助文字、强调/强调文字；透明叠加、主题和图片背景需要重新计算，不凭样例通过豁免。候选不覆盖项目 token。

样例的字号、行宽、断点均是具体方案，非通用阈值；中文规则仍见 typography-cn。下方风格简表继续作为开放维度的词汇参考，不与组合另立一套参数规范。

以下保留启动素材，供未确定的色彩/字体维度参考；不是已验证的完整主题，也不提供行业选型表。色值只是表达候选，须按实际角色组合检查对比度；字体沿项目资产、目标文字与回退选择。布局间距、断点、动效和组件不能从风格名称推断，统一进入[设计契约](design-contract.md)。

| 表达示例 | 可借鉴的视觉语法 | 配色与字体候选 |
|---|---|---|
| 编辑极简 | 细线与排版层级，减少容器装饰；深浅主题均可 | 深底 #0f0f14、文字 #ffffff、强调 #5e6ad2；Inter Tight / Inter，中文回退 PingFang SC |
| 电影深空 | 大尺度影像与少量强色形成焦点 | 黑 #000000、品红 #e219eb、青 #00e5ff；Sora。需真实影像或明确视觉主题，不能遮蔽文本 |
| 暖纸手作 | 材料感与正文节奏表达亲近 | 纸白 #faf8f2、墨色 #2d2a26、赤陶 #9d5f4d；Source Serif，中文宋体。暖色不自动代表所有生活品牌 |
| 数据终端 | 稳定对齐与清晰数据层级 | 底色 #181818、文字 #e0e0e0、强调 #faff69；数据可用 JetBrains Mono 或等宽数字。数据任务不要求暗色或荧光色 |
| 粗野撞色 | 强边界与直接的字形建立节奏 | 白 #ffffff、黑 #000000、橙 #ff6600；Unbounded / Space Grotesk。冲击不能损害文本读取 |
| 液态玻璃 | 用透叠关系解释层级 | 随内容调整透明表面，字体可参考 Outfit；复杂背景需核对可读性和渲染成本，无层级用途时可不用 |
| 杂志编辑 | 图文主次与不等宽分栏表达内容关系 | 暖白 oklch(98% 0.005 80)、墨色 oklch(30% 0.02 60)；Playfair Display / Source Sans Pro，中文宋体标题与黑体正文 |
| 日式禅意 | 留白与少量细节支持慢节奏观看 | #f7f5f0、#33322e、#7a8b78；Zen Old Mincho / 中文宋体。不把密集工作界面强行拉疏 |
| 工业实用 | 严格对齐、明确分区和直接标签 | 铝灰 #e8e6e1、近黑 #1a1a1a、橙 #d97900；IBM Plex Sans / Mono。编号仅用于真实顺序 |
| 复古未来 | 用历史媒介的色彩和字形形成题材联系 | 深棕 #1a1206、琥珀 #ffb000；VT323 / IBM Plex Mono，中文黑体回退。纹理不能影响读数 |

## 从参照回到方案

方案比较与选定沿[入口 D1](../SKILL.md#d1形成方向仅方向尚未确定时)；本参考只提供可借鉴的机制与取舍。已有品牌中可以比较列表/分组、详情位置或信息强调，保持 token 和组件来源一致。无需为了“独特”消除用户熟悉且有效的惯例。
