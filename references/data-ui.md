# 数据界面的表达与判断

涉及指标、表格、图表或其筛选联动的设计选择时读取；已有表达只核对受影响部分，普通数字文案无需整套分析。本文件帮助选择与组织表达，数据定义以项目业务/接口为准，不重新规定后端计算。

## 先明确用户要判断什么

从 brief、真实数据样本与现行口径确认：用户要比较、发现变化、定位异常，还是核对精确记录；需要哪些字段、单位、时间范围与分组。缺少会改变结论的口径时明确未知，不用看似合理的汇总填补。原型数据标模拟。

| 判断任务 | 可用表达及选择理由 | 何时换一种表达 |
|---|---|---|
| 查找、核对精确记录或执行逐项操作 | 表格/列表保留字段关系，按任务安排主列与操作 | 窄屏可展开次要字段；不要把核心比较拆成无法对读的卡片 |
| 比较类别大小或排序 | 条形图便于看差异，配直接标签；需要精确核对时附值或表格 | 名称、分组或项目过多影响定位时，采用筛选、分组或表格，而非固定条数阈值 |
| 看时间变化 | 时间序列保留时间间隔与单位，突出与任务有关的变化 | 只有离散快照或采样不一致时说明含义，不凭平滑曲线制造连续趋势 |
| 看部分与整体 | 在分母明确时显示占比；按精确比较需求选择条形、堆叠或表格 | 类别有重叠、合计无意义或需比较细小差异时，不强行饼图 |
| 看分布或变量关系 | 分布图或散点表达离散程度与关联，并说明轴、样本范围 | 数据不足就展示可支持的事实，不从相关性推断因果 |

选择依据是任务与数据，不是某个行业必须用某张图。已有项目组件与技术栈优先，不因为案例提到某库就引入依赖。

## 口径与联动

- 在判断发生的位置呈现必要的单位、时间范围、时区/比较基准和更新状态；沿项目语言格式，避免让用户从无关角落猜口径。只展示有来源的更新时间，不把当前渲染时间当数据更新时间。
- 区分 0、缺失、未加载和不可用；缺失值不自动变为 0。趋势中的缺口、精度和舍入要保持数据含义，不能让视觉处理改变结论。
- 用长度表达数值时避免截轴夸大差异；时间序列需要局部范围时明确轴范围。跨图比较先核对尺度与统计口径，不把相同颜色当成相同含义。
- 筛选作用于哪些表格、图表和汇总必须清楚；局部指标可保持全局，但要标明范围。查询中、失败或旧数据保留时，不让新筛选标签搭配旧值冒充新结果。
- 表格排序、分页和批量选择应明确作用范围，例如当前页或全部符合条件的记录。刷新后选择是否保留沿项目规则；返回恢复与 URL 状态继续由[交互规则](interaction.md#导航弹层与长内容)维护。

## 窄屏与可访问表达

先保留完成核心判断所需的身份字段、值和动作，再选择换行、展开、列选择或局部横向滚动。需要逐列比较的表格可保留二维结构并提示滚动范围，不能为了“无横向滚动”隐藏必要字段；页面其他部分仍正常重排。

颜色仅辅助编码，使用适用的标签、线型或符号；可访问的关键结论与数据替代见[素材规则](assets.md#可理解的替代内容)。图表 hover 值需有适用的键盘/触摸访问，刷选、缩放等交互沿[交互规则](interaction.md)，数据变化动效沿[动效规则](motion.md)。静态图不补虚构交互。

## 承接与验证

在[设计契约](design-contract.md#任务路径与方向来源)引用所选表达的判断目标、现有数据口径来源及必要联动；已有接口文档不复制一份。验证用已知值和边界样本核对：读数/单位、0 与缺失、筛选前后作用范围、必要的窄屏操作；具体选择随改动范围。源码声明不能证明用户读数无误，实际呈现与操作的证据归[评审规则](review.md)。
