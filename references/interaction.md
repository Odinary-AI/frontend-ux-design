# 交互规则

适用于设计、迭代和评审中的真实交互。只检查任务涉及的控件与流程；状态选择与表达见 [设计契约](design-contract.md)，严重程度和证据见 [评审规则](review.md)。

## 控件与可访问性

- 行为用按钮、导航用链接，优先原生语义或项目已有可访问组件；保留新标签页、键盘等平台惯例。
- 页面有合理的标题层级与语义区域；重复导航前提供适用的跳转主内容入口，局部组件复用页面已有结构。
- 可操作对象有可理解的名称，图标按钮有可访问名称；装饰图标不重复朗读。焦点应清晰且不被固定头部或弹层遮挡。
- 无项目规范时，焦点环可从至少 2px、与相邻背景至少 3:1 对比度起步；其他焦点呈现也需证明可辨认，不能仅靠声明数值认定通过。
- 适用的 default、hover、active、focus、disabled、selected 等状态可辨认；触摸不能依赖 hover，语义不能只靠颜色传达。
- 项目无规定时触控目标以 44×44 CSS px 为设计目标；小图标可扩展点击区。不能仅凭元素尺寸就宣称 WCAG 通过或失败。
- 键盘路径可完成核心任务且没有焦点陷阱；自定义拖拽/手势需提供适用的点击与键盘替代，不将鼠标可用当成触摸已验证。

## 表单与恢复

- 标签对应输入，字段的 type、inputmode、autocomplete 与任务匹配；不阻止粘贴，不破坏密码管理器或输入法组合输入。
- 校验信息定位到字段；提交失败后可找到错误并修正，保留已有输入。校验时机沿项目约定，不在每次输入时反复打断用户。
- 请求中给出反馈并防止重复提交；失败可恢复，成功不留在含糊的 loading 中。异步状态变化需要时通过 live region 等机制通知辅助技术。
- 低风险、可恢复动作可用撤销；不可逆或高影响操作使用与风险相称的确认。不能仅为减少点击取消必要确认。
- 离开未保存工作时沿项目行为提示或保存；不将自动保存、后端幂等、权限能力等臆造为已实现。

等待反馈匹配真实请求。快速返回时直接显示内容，避免骨架闪现，不为展示效果延迟结果；确有等待时骨架贴合内容结构，涉及运动的表现按 [动效规则](motion.md)。乐观更新仅用于低风险且有真实失败回滚路径的操作，区分暂定结果与服务确认；高风险操作不提前宣称成功。

## 导航、弹层与长内容

- 筛选、分页或标签状态需要分享/返回恢复时采用项目已有 URL 或状态持久化方式，不把所有临时 UI 状态塞进 URL。
- 弹层有标题/名称，打开与关闭后的焦点去向明确；模态层避免背景被误操作，按组件约定处理 Escape、焦点管理和滚动。优先复用组件，不另造一套 portal/z-index 系统。
- 长标签、空集合、加载中、图片失败和局部错误均有合理呈现；信息截断有必要时提供访问完整内容的方法。
- 列表按实际规模与性能选择分页或虚拟化，不凭固定条数引入复杂实现。

## 移动交互

- 用输入能力判断 hover/触摸行为，不靠屏幕宽度猜测设备；混合输入设备应能同时工作。
- 全屏应用、底部操作区需检查浏览器工具栏、软键盘和安全区；按布局需求选择动态/稳定视口单位，保留项目支持范围内的回退。
- 移动输入框应避免浏览器聚焦放大带来的布局问题；不要以禁止页面缩放代替修复。
- 抽屉/弹层的滚动不意外带动背景；拖拽处理 pointer cancel、丢失捕获与中断，不能使页面卡在拖拽状态。
- 拖拽期间只在必要区域抑制选择或滚动；正文、地址和错误信息保持可复制。
- 桌面窄屏截图只支持布局观察。触摸合成、模拟器和真实设备分别说明；没有设备时明确软键盘、触感和浏览器行为的未验证部分。

## 文案

动作名称在按钮、加载、结果提示中保持一致。优先动作加对象，短词在语境足够明确时可用，不机械禁用所有“确定”。错误说明发生了什么、已知原因和下一步；不知道原因就不编造。空结果解释原因并提供适用的下一步，不给无权限用户虚假的创建入口。

沿项目语言与品牌规范选择标题大小写、标点、数字日期格式；不混用外部作者的互斥偏好。多语言时检查真实内容长度和本地格式，避免固定宽度假定所有语言一样短。
